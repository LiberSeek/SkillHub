# sk-industry-researcher

这是一个给工作室使用的行业研究入口。

它 vendor 自上游 `luopan`，但按工作室习惯做了重新命名和包装。目标不是输出百科，而是尽快形成：

- 核心判断
- 上中下游权力结构
- 代表公司清单
- 行业前景与行动建议

## 什么时候用

- 你要快速理解一个陌生行业
- 你要判断一个赛道值不值得做
- 你需要给内容选题、创业判断、求职决策做前置研究
- 你想知道一个行业里“谁真正有话语权”

## 不适合的场景

- 需要实时行情、实时股价、实时政策解读的投资决策
- 需要付费数据库才能完成的严谨尽调
- 只想看百科式定义，不需要结构化判断

## 默认输出

至少输出 4 件事：

- 一个答案先行的核心判断
- 一张上中下游权力分布图谱
- 一份代表公司分析清单
- 一组是否进入这个行业的行动建议

推荐结构：

```text
核心判断

一、最少必要知识
一句话定位 + 行业怎么运转 + 核心术语 + 关键数字

二、商业模式与竞争格局
上中下游权力分布 + 代表公司 + 分类理由 + 关键数据

三、行业前景
趋势信号 + 核心风险 + 未解决争论 + 行动建议
```

## 工作原则

### 1. 不输出百科，输出判断

每个重要判断尽量都带上：

- 数据
- 来源
- “所以呢”

不要只罗列信息。

### 2. 上中下游按权力划分，不按产业链位置划分

这里的“上游”优先指：

- 定价权更强
- 议价能力更强
- 客户替换成本更高
- 更接近利润池

不是谁在原材料端谁就天然叫上游。

### 3. 诚实比完整更重要

- 搜不到就明确说“公开信息有限”
- 矛盾数据并列呈现，说明可信度
- 未证实信息必须标注未证实

### 4. 先形成假设，再主动推翻

不要等所有信息齐了再开始判断。

先给一个 Day-1 假设，再用后续搜索和阅读修正它。

## 推荐工作流

### Phase 0：先判断用户为什么要研究这个行业

优先判断研究目的更偏向：

- 求职
- 创业
- 内容选题
- 通用理解

这会影响后面“人才端 / 商业端 / 内容端”的权重。

### Phase 1：热身搜索，先摸全貌

至少覆盖这些问题：

- 行业主要是做什么的
- 市场规模大概多大
- 关键公司有哪些
- 钱主要在哪些环节赚
- 最近 1-2 年最大的变化是什么

### Phase 2：先写 Day-1 假设

用 1-2 句话写出当前判断，例如：

- 这个行业的利润主要被平台拿走，而不是被内容方拿走
- 这个行业正在从分散走向集中，头部公司话语权变强
- 这个赛道看起来热，但真正吃到利润的不是表层玩家

### Phase 3：梳理权力结构

把公司放进三层：

- 上游：最有话语权、最接近利润池
- 中游：有能力但仍受制于平台、供给或渠道
- 下游：可替代性强、利润薄、容易被挤压

每家公司至少说明：

- 商业模式
- 关键数据
- 为什么被分到这一层

### Phase 4：补深度信息

优先查：

- 官方财报、公告、招股书
- 行业报告、券商研报、权威媒体
- 招聘信息、岗位结构、融资动态

如果行业更偏消费或内容，要多看需求端和平台端。

如果行业更偏科技或制造，要多看技术壁垒和产业链位置。

### Phase 5：对抗验证

把自己切到“挑刺者”视角，再过一遍：

- 有没有结论听起来有道理，但没数据支撑
- 有没有把相关性当因果
- 有没有拿不同时期、不同口径的数据硬比
- 有没有把知名度误当成权力

## 输出要求

- 标题尽量直接表达判断，不只写主题词
- 结论优先，定义和背景放后面
- 多用对比，少用空泛形容词
- 能量化就量化，不能量化再定性

## 推荐补充项

如果用户目标更明确，可以额外补：

- 求职建议：哪些岗位值得看，哪些能力最稀缺
- 创业建议：哪个环节最有机会，哪个环节最容易被平台压制
- 内容建议：这个行业最值得切的选题角度
